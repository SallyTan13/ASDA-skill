## How to Use

**Step 1: Identify question type**  
Read the question carefully and determine which financial subfield it belongs to (corporate finance, derivatives, portfolio management, fixed income, equity, financial statement analysis, economics, or alternative investments). Then identify the error type: concept confusion, visual evidence, unit/currency/percent issues, code execution errors, wrong method selection, missed constraints, wrong targets, or missed multi-step reasoning. Map to one or more entries in the File Index above.

**Step 2: Request relevant skill file**  
Use the `load_skill_file` tool with the exact File Path from the File Index table. You may need to load multiple files if the question spans multiple error types or subfields (e.g., visual evidence + concept confusion).

**Step 3: Apply pattern from the loaded file**  
1. Scan the loaded skill file to find the pattern that matches your question's structure  
2. Follow the procedure section of that pattern step-by-step  
3. Copy the code template structure from the pattern's example  
4. Replace all placeholders with actual values from the question  
5. Ensure the final line is a variable name or expression (not `print()`), so `eval()` can capture the result  
6. Verify all imports are at the top and all variables are defined before use  

**Example**  
- *Question:* "Based on Exhibit 2, calculate the portfolio's expected return and standard deviation. Which portfolio lies on the efficient frontier?"  
- *Step 1:* Portfolio management + visual evidence (table extraction) + unit/currency/percent (return calculations).  
- *Step 2:* Request `common/visual_evidence.md` and `portfolio_management/unit_currency_percent.md`.  
- *Step 3:* Apply "Table Structure Parsing and Row-Column Alignment" from visual_evidence.md to extract data, then apply "Portfolio Expected Return Calculation" and "Portfolio Variance and Standard Deviation from State Returns" from unit_currency_percent.md to compute metrics. End with the variable containing the answer.

## Critical Code Constraints (ALWAYS FOLLOW)

**Your code MUST:**  
- End with a variable name or expression (for `eval()` to capture the result)  
- Put all imports at the top (e.g., `import numpy as np`, `from scipy.optimize import brentq`)  
- Define every variable before use with explicit values from the question  
- Use proper sign conventions (e.g., negative for outflows in NPV/IRR calculations)  
- Convert percentages to decimals when performing arithmetic operations  
- Use appropriate rounding only at the final output stage  

**Your code MUST NOT:**  
- Use `input()` or other interactive functions  
- Use `print()` as the last line (this returns `None` instead of the computed value)  
- Reference undefined variables or rely on variables from examples without redefining them  
- Use placeholder values like `X` or `TODO` — all values must be concrete  
- Mix percentage and decimal formats inconsistently within calculations  

**Available libraries:**  
- `import math` — standard mathematical functions (sqrt, log, exp, etc.)  
- `import numpy as np` — numerical operations, arrays, linear algebra  
- `from scipy.stats import norm` — normal distribution CDF/PDF (for Black-Scholes, VaR, etc.)  
- `from scipy.optimize import brentq` — root finding for IRR, implied volatility, yield-to-maturity  
- `from scipy.optimize import fsolve` — alternative root finding for systems of equations  

## When NOT to Use

- **Qualitative questions**: When the question asks for conceptual explanations, definitions, or theoretical frameworks without numerical computation (e.g., "Explain the difference between systematic and unsystematic risk").
- **Pure data retrieval**: When the answer is directly stated in the text or table without requiring calculation (e.g., "What is the company's reported net income in 2023?").
- **Non-financial domains**: When the question is outside finance/economics (e.g., pure statistics, physics, or general programming problems).
- **Symbolic mathematics**: When the question requires symbolic manipulation or algebraic proofs rather than numerical computation.
- **Insufficient information**: When the question lacks the necessary numerical inputs to perform calculations and no reasonable assumptions can be made from context.
